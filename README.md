# Loan Eligibility Dashboard

A FastAPI + Pydantic backend serving a trained RandomForest loan-eligibility
model, with a static dashboard frontend (charts + a live prediction form).
Deployable to Vercel as serverless functions.

## Project structure

```
loan-dashboard/
├── api/
│   ├── index.py          # FastAPI app (all /api/* routes)
│   └── schemas.py         # Pydantic request/response models
├── public/
│   └── index.html          # Dashboard frontend (vanilla JS + Chart.js)
├── model.joblib             # Trained RandomForestClassifier
├── model_metadata.json      # Encoders, feature list, metrics
├── Loan_Eligibility_Prediction.csv
├── train_model.py           # Re-run to retrain the model
├── requirements.txt
└── vercel.json               # Routes /api/* to Python, rest to static files
```

## Run locally

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
pip install uvicorn

# Retrain the model if you change the CSV or pipeline:
python3 train_model.py

# Run the API
uvicorn api.index:app --reload --port 8000
```

Then open `public/index.html` directly in a browser, or serve it:

```bash
cd public && python3 -m http.server 3000
```

If serving the frontend separately from the API, change the `API` constant
at the top of the `<script>` block in `index.html` to `http://localhost:8000`.

## API endpoints

| Method | Path                  | Purpose                                   |
|--------|-----------------------|--------------------------------------------|
| GET    | `/api/health`         | Health check                              |
| POST   | `/api/predict`        | Predict approval for one applicant        |
| GET    | `/api/metrics`        | Model accuracy, confusion matrix, feature importance |
| GET    | `/api/dataset-summary`| Aggregate dataset stats for dashboard charts |

All request/response bodies are validated with Pydantic (see `api/schemas.py`),
so invalid input (e.g. negative income, bad enum values) returns a 422 with
a clear error before it ever reaches the model.

Interactive API docs are auto-generated by FastAPI at `/api/docs` once deployed
(and `http://localhost:8000/docs` locally).

## Deploying to Vercel

### 1. Install the Vercel CLI (if you don't have it)

```bash
npm install -g vercel
```

### 2. Log in

```bash
vercel login
```

### 3. Deploy from the project folder

```bash
cd loan-dashboard
vercel
```

Follow the prompts:
- **Set up and deploy?** Yes
- **Which scope?** (choose your account)
- **Link to existing project?** No (first time)
- **Project name?** loan-eligibility-dashboard (or whatever you like)
- **Directory?** `./` (current directory)
- Vercel auto-detects `vercel.json` and builds the Python function + static site.

This gives you a preview URL like `https://loan-eligibility-dashboard-xxxx.vercel.app`.

### 4. Deploy to production

```bash
vercel --prod
```

### 5. (Optional) Deploy via Git instead of CLI

- Push this folder to a GitHub repo.
- Go to https://vercel.com/new, import the repo.
- Vercel reads `vercel.json` automatically — no extra config needed.
- Every push to `main` redeploys automatically.

### Notes on the Vercel Python runtime

- `vercel.json` uses `@vercel/python`, which installs `requirements.txt` and
  runs `api/index.py` as a serverless function (FastAPI app is auto-detected
  via the ASGI `app` object).
- `model.joblib` (~300 KB) and `model_metadata.json` are bundled with the
  function automatically since they live in the project root and are
  referenced by relative path — no external storage needed.
- Cold starts install the pinned `scikit-learn`/`pandas` wheels; keep versions
  pinned in `requirements.txt` to avoid rebuild surprises.
- If you outgrow the free tier's function size limit, swap `RandomForestClassifier`
  for a lighter model or move `model.joblib` to a blob store and load it at
  runtime.

## Retraining

Edit `train_model.py` if you change features or hyperparameters, then:

```bash
python3 train_model.py
```

This regenerates `model.joblib` and `model_metadata.json`, which you can
commit and redeploy.
